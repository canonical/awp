# Review of `fips-skill-spec.md`, revision 2

**Verdict.** Revision 2 is implementable. Of the 25 findings of the first report, 23 are resolved and 2 are partially resolved (B3: the README parametrisation misses line 98, the RMF feedback file name; S2: one citation still attributes the level names to a section that does not contain them). Every PDF claim I re-checked against `pdftotext` is correct, including the verbatim quotes, the two numberings, the sha256 and the page count. Every file:line claim about the templates and tests is correct. The new problems are smaller than those of revision 1: a wrong statement about the position of the `copied` line in the exact output (sorted by name, not by layer, and `.gitignore` comes first), an undefined notion of "the `RQ#` line" that two reasonable linter implementations would read differently, a `time-loop` driver table that omits the one thing `time-loop` actually reads from the report (the scenario tag and scale: `RS#` + High/Moderate/Low vs `VO#` + `P1`–`P3`), and an understated consequence of dropping STRIDE (the crosswalk §3 ledger that `frama-c-monitoring`'s Gate C and `bin/ledger-ratchet.sh` work on has no FIPS form). On the §6 design decision: installing both drivers always is sound and the reading of "uses `fips-sl` instead of `rmf-sl`" as "is driven by" is defensible, but open point 8 lists only the alternative's costs, not the chosen design's, and omits a cheap intermediate option; the user should decide with both sides in view.

## 2. New findings

### Blocking

None.

### Should fix

**S-1. The `copied` line for the PDF is not first, and not for the stated reason (§3, §8).**
- Spec: "The `tools` step prints one more line for both languages, first, because the common layer is copied before the language layer."
- Evidence: `install_tools` merges all layers into one dict and emits in `sorted(chosen)` order (`auto-wp.py:149-168`); the layer order plays no part. `templates/c/tools/` holds a `.gitignore` (`ls -a`), and `test_c_output_exact` expects `copied  foobar/.gitignore` as the first `copied` line (`tests/test_auto_wp.py:606-611`). `.gitignore` < `NIST.FIPS.140-3.pdf` < `bin` in byte order, so for C the PDF line is second; for Rust it is the only one.
- Fix: "`copied  foobar/NIST.FIPS.140-3.pdf` appears between `copied  foobar/.gitignore` and `copied  foobar/bin` for `--c` (entries are emitted in sorted name order), and is the only `copied` line for `--rust`." Update the §8 `test_c_output_exact` bullet accordingly.

**S-2. README line 98 is RMF-specific and not parametrised (§7.3).**
- Evidence: `templates/c/README.md:98` names "the numbered `grub-analysis-monitor-feedback-NN.md` files"; §4.3 and §7.1 name the FIPS packet `PREFIX-fips-feedback-NN.md`. A `fips` README would point at files that never exist.
- Fix: add a placeholder `{{FEEDBACK}}` → `monitor-feedback` / `fips-feedback` (line 98 becomes `grub-analysis-{{FEEDBACK}}-NN.md`), and extend T5's expected set to `{DIR, LANGUAGE, DRIVER, DRIVER_LINE, FEEDBACK}` for C; or rename the FIPS packet to `PREFIX-monitor-feedback-NN.md` and say so in §4.3 and §7.1. Either way, say which.

**S-3. "The `RQ#` line" is undefined; F-C4, F-C5, F-C6 and F-C7 depend on it (§4.4 rules 3-4, §5).**
- Evidence: `RQ#` tokens appear by design on `FM#`, `VO#` and `RR#` lines (rule 4), which carry no `AR#` and no `src:`. `rmf-lint.sh`'s primitive is `lines_with(id)`, every line mentioning the id (`rmf-lint.sh:56-58`), and its chain checks pass when *any* such line satisfies the rule (the back-reference masking the format doc warns about, `rmf-sl/references/report-format.md:18-24`). Read as "every line mentioning `RQ#`", F-C4 fails on every `FM#` line; read as "some line", the canary "`VO#` without its `RQ#`" can be masked by any other line naming both ids.
- Fix: define "the `X#` line" as the line in X's home section (F1-F5 per the §4.4 table) that contains `X#`, require exactly one per id (fold into F-C4/F-C6 or add F-C0), and state that mentions outside the home section are references and are not checked. Then F-C4/F-C5/F-C7 apply to F2 lines, F-C6 to F3/F4/F5 lines.

**S-4. The `time-loop` driver table omits what `time-loop` reads from the report (§7.1).**
- Evidence: `time-loop` keys its monotone-coverage gate, Gate C, the Plane-H selector and the Monitor packets to `RS#` scenarios and their risk level (`time-loop/SKILL.md:142,154,294,321,537`; "Tier-3 authorization/integrity-logic RS#"). A FIPS report has `VO#` with `P1`-`P3` and property classes; no tiers. The table maps command, files, linter and terminus only, so "the RMF-specific text stays and is read through the table" does not hold for the ranking or for the W/H plane split.
- Fix: add two columns: scenario tag + scale (`RS#`, `High/Moderate/Low` | `VO#`, `P1`-`P3`) and Plane-H selector (Tier-3 EoP/integrity `RS#` | `VO#` whose class is one of the six system-level classes of §4.5). Also add `time-loop/SKILL.md:973` (`config/commands/rmf.md`) to the places the table replaces.

**S-5. Dropping STRIDE removes the crosswalk §3 coverage ledger; its consequence for `frama-c-monitoring` is unstated (§7.1, §9 point 4).**
- Evidence: the canonical crosswalk schema has a "§3 STRIDE coverage ledger — asset × {S,T,R,I,D,E} (the Gate-C surface)" (`frama-c-monitoring/templates/crosswalk-template.md:42`); `frama-c-monitoring` bootstraps `bin/ledger-ratchet.sh` on it (`SKILL.md:464,857-858`); `ledger-ratchet.sh` parses `asset<TAB>S..E` rows and SKIPs with exit 0 when no ledger is present (`ledger-ratchet.sh:2-23`). A `fips-crosswalk.md` with no §3 makes the cross-run ratchet a no-op in every `fips` project, silently. Open point 4 gives "a longer report" as the only cost of keeping STRIDE.
- Fix: in §7.1 say that `fips-crosswalk.md` carries no §3 ledger and that `ledger-ratchet.sh` therefore SKIPs (acceptable, honest), or specify a FIPS ledger `AR# × property class` with the same cell lifecycle and extend `ledger-ratchet.sh` to parse it; record the choice in open point 4.

**S-6. Open point 8 is one-sided (§6, §9 point 8).**
- The chosen design is sound (no dangling links, no code change to the copy functions) and "uses" can mean "is driven by". But point 8 lists only the alternative's costs. The chosen design's costs are absent: a `fips` project ships `rmf-sl`, `/rmf`, `bin/rmf-lint.sh` and a README that still advertises `/rmf` (line 130); an `rmf` project ships a `/fips` that stops on a missing `fips_level`; the manifest's `skills` and `commands` are identical under both drivers, so `driver` is the only discriminator; and `--driver fips` differs from the default in four surface items, which is a thin reading of "instead of".
- Also missing: an intermediate option. `copy_commands` works per file (`auto-wp.py:134-145`), so skipping only the *other driver's command* (`rmf.md` or `fips.md`) is a one-line filter; the only references to `commands/rmf.md` outside itself are `time-loop/SKILL.md:973` (covered by the table) and README line 130 (already parametrised). This gives "instead of" a visible meaning without touching `bin/` or the skill cross-links.
- Fix: list both sides and the intermediate option, then let the user choose.

### Minor

**M-1. Sec. 1 does not name the levels (§1 table, row 1).** Sec. 1 reads "requirements for four security levels" and "Four security levels were specified for each of eleven requirement areas"; only Ann. 3 writes "Level 1, Level 2, Level 3, and Level 4". Cite Ann. 3 alone for the names, Sec. 1 for the count of levels and areas.

**M-4. `time-loop.sl.json` `monitors` is a single string (§7.1, §8 T8).** The schema types `monitors` as `string|null` (`sl-internal/references/sl-schema-1.0.json:49-52`), and today it is `"rmf-sl"` (`time-loop.sl.json:8`). A "driver table" cannot go in that field. State what it becomes (keep `rmf-sl`, or `null` with the table in `description`/`notes`), and note that two-file mode only emits an INFO when `monitors` does not name the base (`sl_disjointness_check.py:237-239`), so the T8 pairing with `fips-sl.sl.json` passes trivially unless source ids are shared.

**M-5. T9 needs a machine-locatable fixture (§5, §8).** "The minimal skeleton in `report-format.md`" has to be extracted by the test. Say how: a fenced block with a fixed info string (e.g. ```` ```markdown fips-skeleton ````) or a separate `references/skeleton.md`; and say the broken copies are string edits of that skeleton made by the test. Also note `test_templates.py`'s docstring ("They only read templates/", `:1-6`) must change, since T9 runs a script.

**M-6. `/fips` flag aliases (§7.1).** `rmf.md:18-20` recognises `--fresh`/`--force` and `--monitor-only`/`--quick`; the spec lists `--fresh` and `--monitor-only` only. Say "with their aliases".

**M-7. Form of the level line (§4.4 rule 6).** `^level: [1-4]$` excludes a Markdown bullet (`- level: 3`), which a report author following rule 0's "one artifact per list item" is likely to write. Say the line is a bare paragraph line and show it in the skeleton.

**M-8. `grub-core/lib/libgcrypt` (§7.3, §9 point 2).** No GRUB checkout is available here, so the path is unverified offline; it matches the GRUB tree as I know it (`grub-core/lib/libgcrypt/{cipher,mpi,src}`, imported from libgcrypt). Mark it "to be confirmed on the clone" until a Level-3 run checks it.
